{% comment %} The comparison table on /pricing/, below plans-bands.html. The two are not rivals and neither is going away: the bands are for choosing (each level argued on its own terms, in the order the commitment grows) and this table is for verifying (every axis named once, in a frozen left column, so a row can be read straight across). People do both, in that order, and the table is where a careful buyer checks the claim the cards made. HOSTED LEVELS ONLY. "You build it" is not a column here. The free download has nothing to compare on - the answer to nearly every row is "your server, your rules" - so its column was a stack of the same shrug, and it squeezed the four paid levels for the reader who is actually choosing between them. It is still the first card in plans-bands.html, which is where someone decides whether to host at all; this table is for the decision after that one. The Download button stays off the CTA row for the same reason. WHAT NEVER VARIES IS NOT A ROW. Unlimited everything, full AI, and security /updates/monitoring are promised at the top of /pricing/ for every plan, so a row each was four identical cells restating the page's own opening. Only what actually differs between levels earns a row here. Same axes, in the same order, as the cards in plans-bands.html - if you add one there, add it here. Support is four rows rather than one because it escalates on four separate counts: how directly you can reach us, how fast we answer, how much we do once we have, and whether changing the system is included at all (see the support note in plans-bands.html). Scroll sideways to move through the levels; the row labels stay put. PRICES ARE PLACEHOLDERS, matching plans-bands.html. Change both together. The header prices are the annual rate, as the cards' prices are; the month-to-month rate is on the cards alone, in each card's note, because a second price per column is a second thing to read in a table whose job is to make one row readable straight across. {% endcomment %}
