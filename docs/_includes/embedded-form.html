{% comment %} Embeds one Formulize screen from formulize.net into a page here. Usage: {% include embedded-form.html sid="1" title="Get help with Formulize" height="900" %} Parameters: sid the screen id on the Formulize site. 1 = Help Request, 3 = Get your own Formulize system. It has to be the sid, not the screen's prettier rewrite address (get-help, get-hosting): those do not resolve when the request comes from another domain, which is exactly the case here. Copy the sid from the screen's settings page, which is also where the rest of this markup comes from. title the iframe's accessible name. Required - it is what a screen reader announces when it reaches the frame. height starting height in pixels, before the screen reports its real one. Pick something close to the finished form so the page does not jump. The script is emitted once per page however many screens the page embeds, which is what formulize-embed.js expects. assign is page-scoped in Jekyll's Liquid, so the flag survives from one include call to the next. IMPORTANT - submissions and the same-domain rule. site.forms_url currently points at formulize.net, which is a different domain from this site. Browsers will not send the Formulize session cookie into a frame across domains, so the form displays but saving fails. The fix is an alias of the Formulize site on this domain (forms.formulize.org) - see docs/embedding_screens_setup. Until that exists, the "open in its own window" link below the frame is the route that actually works, and the sessionUnavailable handler promotes it the moment the screen reports the problem. PLAN PRE-SELECTION - /pricing/ and /signup/'s plan cards link here as ?plan=level-1..4. The iframe's src is deliberately NOT set directly in the HTML below (it's stashed in data-embed-src instead): a plain src attribute starts loading immediately, before this page's own ?plan= param could be read and appended, so the frame would always load without it. Building the final src in the script below, forwarding the current page's own ?plan= if present, means it's there from the very first request the frame makes - see hosting_requests_which_plan on the Hosting Requests form (form 2), which has a small script element of its own that reads it back out of window.location.search inside the frame and pre-selects the matching radio button. Harmless no-op on a screen with no such element and on a request with no ?plan= param. {% endcomment %}

Trouble with the form? Open it in its own window, or email info@formulize.org and we will pick it up from there.
